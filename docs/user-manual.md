# Руководство пользователя

Для кураторов волонтёрской программы и сотрудника, который обслуживает систему. Как её установить —
в [install.md](install.md); здесь — как ей пользоваться каждый день.

## 1. Как всё устроено

```
Кандидат пишет сообществу ВКонтакте
   → бот проводит его по анкете и задаёт уточняющие вопросы
   → анкета оценивается по рубрике музея, карточка приходит в беседу кураторов
   → куратор открывает дашборд: рейтинг, карточка кандидата, решение
   → «Сборка команды» раскладывает кандидатов по направлениям
   → через четыре месяца бот спрашивает взятых волонтёров, как дела
   → ответы учат прогноз активности для следующих наборов
```

Решение о кандидате всегда принимает куратор. Система подсказывает: балл, цитаты из анкеты, замечания,
вопросы для собеседования и прогноз — но никого не отбирает сама.

## 2. Бот глазами кандидата

**Как начать.** Кандидат пишет сообществу музея в личные сообщения любое слово — бот присылает приветствие,
рассказ о направлениях и кнопку «Начать анкету». Ссылку на диалог можно разместить в постах и на сайте:
`https://vk.me/<короткое имя сообщества>`.

**Анкета.** Около 20 вопросов, 10–15 минут. Большинство — кнопками, текстом нужно ответить на 7–8 открытых:
ФИО, почта, дата рождения, научные интересы, опыт, хобби, «почему ГИМ», ожидания. Часть вопросов задаётся
не всем: вуз и курс — только студентам, дорога — тем, кто живёт в области.

**Уточнения.** После ответов про опыт, хобби, мотивацию и ожидания бот может задать один уточняющий вопрос
по словам кандидата (не больше трёх за анкету), а в конце — ещё 2–5 коротких. На любой можно нажать «Пропустить».

**Кнопки и слова, которые понимает бот:**

| Что | Что происходит |
|---|---|
| «← Назад» | вернуться к прошлому вопросу |
| «Продолжить позже» | ответы сохраняются; любое сообщение потом вернёт к тому же вопросу |
| «Пропустить» | пропустить уточняющий вопрос |
| «Исправить ответ» | в конце, на проверке ответов: выбрать номер пункта и ответить заново |
| «Начать заново» (написать текстом) | начать анкету с начала |

Кто бросил анкету, через сутки получает одно напоминание. Кандидаты младше 18 лет анкету не продолжают —
бот вежливо объясняет почему.

**После отправки** кандидат получает благодарность и подсказку, какое из выбранных им направлений,
судя по анкете, подходит ему больше и почему. Подсказка никогда не обещает приём.

## 3. Беседа кураторов во ВКонтакте

Сюда бот присылает:

- **карточку каждой новой анкеты** — примерно через минуту после отправки: ФИО и ссылка на страницу,
  оценка и балл, прогноз активности, баллы по факторам, замечания («1 курс, очно», «дорога больше часа»…),
  что видно на открытой странице ВКонтакте, краткая характеристика, рекомендуемое направление
  и вопросы для собеседования;
- **сигнал о недовольном волонтёре** — по итогам опроса через четыре месяца (раздел 6);
- **сообщение об обновлении модели прогноза**, когда она переобучилась на ответах опроса.

Если сообщество удалили из беседы или беседу пересоздали, напишите в ней `/id` и передайте номер
сотруднику, который обслуживает систему (он вписывает его в файл `.env` как `VK_CURATOR_PEER_ID`).

## 4. Дашборд

Открывается в браузере по адресу, который даст сотрудник, обслуживающий систему
(на самом сервере — http://localhost:8501). Если задан пароль, дашборд сначала спросит его.

### Боковая панель

- **Набор** — «Текущий набор» (анкеты из бота) или «Прошлые наборы» (таблицы музея, раздел 7).
- **Свободных мест** — сколько человек музей готов взять; от этого числа считаются «Лучшие на N мест»
  и карточка «Приглашено».
- **Важность факторов** — ползунки от 1 до 5. Двигайте, если в этом наборе что-то важнее обычного
  (например, свободное время перед большим фестивалем): рейтинг пересчитается сразу.
  Кнопка «Вернуть важность по рубрике музея» возвращает исходные веса. Файл с рубрикой при этом не меняется.
- **Скачать Excel** — все кандидаты: рейтинг с баллами и решениями, ответы, вопросы для собеседований, сводка.

### Разделы

| Раздел | Зачем |
|---|---|
| **Обзор** | картина набора: сколько анкет, сильных, с замечаниями, сколько приглашено; на столбик графика можно нажать — откроется список этих кандидатов |
| **Все кандидаты** | рейтинг с фильтрами по оценке и направлению, поиском и сравнением нескольких кандидатов |
| **Кандидат** | один человек подробно: балл, сильные и слабые стороны, характеристика, вопросы для собеседования, ответы анкеты, решение куратора |
| **Сборка команды** | раскладка кандидатов по направлениям с учётом мест (раздел 5) |
| **Волонтёры** | итоги опроса через четыре месяца и история обучения модели (раздел 6) |

### Как читать цифры

- **Балл анкеты (0–100)** — насколько анкета соответствует рубрике музея: 70 и выше — сильная,
  55–69 — хорошая, 40–54 — средняя, ниже — слабая. Балл ставится за конкретику (что человек делал, где, зачем
  ему ГИМ), а не за длину ответов.
- **Прогноз активности** — вероятность, что человек станет активным волонтёром (от 20 часов в год),
  по опыту прошлых наборов. Это ориентир, а не приговор: данных пока немного.
- **Замечания** (жёлтые метки) — повод уточнить на собеседовании, а не причина отказа:
  первый курс очно, дорога больше часа, только фонды, мало часов, расхождения с профилем ВКонтакте.
- **«Проверьте»** в карточке — нейросеть в чём-то не уверена (например, отнесла опыт к категории
  без явных слов); стоит прочитать ответ самому.

### Решение куратора

В карточке кандидата — четыре варианта, сохраняются сразу, без кнопки «Сохранить». Комментарий тоже.

| Решение | Когда ставить | Что дальше делает система |
|---|---|---|
| Пригласить | зовём на собеседование | считается в карточке «Приглашено» |
| Резерв | подойдёт, если освободится место | — |
| Отказ | не подходит | кандидат больше не участвует в «Сборке команды» |
| Взят в команду | после собеседования, человек стал волонтёром | через четыре месяца бот пришлёт ему опрос |

Ставьте «Взят в команду» вовремя: от этой даты считаются четыре месяца до опроса. Если поправить только
комментарий, срок не сдвинется.

## 5. Сборка команды

1. Введите, сколько мест в каждом направлении.
2. Система разложит кандидатов: каждый попадает в одно из выбранных им направлений — туда, где он сильнее
   (половина — балл анкеты, половина — прогноз активности, плюс совет нейросети по направлению).
   В фондовое направление попадают только свободные по будням.
3. У каждого — объяснение, почему он здесь; внизу — кто не попал и почему.
4. Нужно взять человека в конкретное направление — «Закрепить вручную», остальные перераспределятся.
5. Поменяйте числа мест, чтобы посмотреть «что если» (например, фондам дали на одно место меньше).
6. «Пригласить собранную команду» ставит всем решение «Пригласить» и записывает направление в комментарий.

Отказанных и уже взятых в команду система не распределяет.

## 6. Опрос волонтёров через четыре месяца

Через 120 дней после решения «Взят в команду» бот сам пишет волонтёру: шесть коротких вопросов —
доволен ли, оправдались ли ожидания (бот цитирует, что человек писал в анкете), хочет ли продолжать, сколько
часов в месяц уходит, посоветует ли друзьям, что изменить. Можно ответить «Не сейчас» или «Не хочу».
Если не ответил — одно напоминание через три дня, через две недели опрос закрывается.

**Сигнал кураторам.** Если волонтёр поставил 1–2 из 5, ожидания не оправдались, он не хочет или не уверен,
что продолжит, или не посоветует программу — в беседу кураторов приходит сообщение с причиной и его
пожеланиями. Это повод поговорить с человеком, пока он не ушёл.

**Раздел «Волонтёры»** в дашборде: сколько опросов отправлено и пройдено, средняя оценка, доля тех,
кто хочет продолжать, список «требуют внимания», все ответы и история модели.

**Как модель учится.** Ответ «продолжу и уделяю от 5 часов в месяц» считается примером успешного волонтёра.
Когда таких ответов набирается пять новых, модель прогноза переобучается сама и остаётся новой, только если
угадывает не хуже прежней. Делать для этого ничего не нужно.

## 7. Данные прошлых наборов

Таблицы музея с прошлыми наборами нужны, чтобы видеть их в дашборде («Прошлые наборы») и чтобы прогноз
активности учился на реальных часах волонтёров.

### Загрузить таблицы

1. Положите файлы Excel в папку `data/history/` проекта (например, `Анкеты 2024 осень.xlsx`).
2. Проверьте, что каждый лист перечислен в `config/history.yaml` — для наборов 2024 и 2025 годов записи уже есть.
3. Запустите:

   ```bash
   docker compose run --rm bot python scripts/import_history.py
   ```

Команда сведёт листы в одну таблицу и исправит форматы, оценит анкеты по рубрике через GigaChat и переобучит
прогноз. Первый раз это занимает около получаса (сотни запросов к GigaChat); повторно — минуты: уже оценённые
анкеты не оцениваются заново. Без ключа GigaChat можно добавить `--no-llm` — тогда оцениваются только пункты,
которые считаются правилами.

### Добавить набор этого года

Если отбор этого года прошёл без бота (по Google-форме или вручную), его можно добавить к прошлым наборам:

1. Сделайте лист с теми же столбцами, что «Ответы на форму (1)» в таблице весны 2025: ответы анкеты
   (ФИО, Дата рождения, ВУЗ, Факультет, Курс, Опыт работы, Интересующие направления, Чего Вы ожидаете, Ваше хобби,
   Откуда…) и итоги отбора — «Сколько баллов», «Взяли ли», «Длительность», «Еще состоит», «Активность».
   Названия столбцов должны начинаться так же, порядок неважен.
2. Положите файл в `data/history/` и допишите в `config/history.yaml` запись по образцу уже имеющихся:
   имя файла, имя листа, короткий код (например, `F26`), название набора, дата собеседований, дата старта.
3. Запустите `import_history.py`, как выше.

### Обновлять часы активности

Прогноз учится на том, сколько часов волонтёры реально провели в программе. Раз в полгода:

1. Впишите в таблицах свежие значения «Активность» (сумма часов за всё время) и «Еще состоит».
2. В `config/history.yaml` поменяйте `ref_date` на дату, на которую эти числа верны.
3. Запустите `import_history.py`.

Волонтёров, которые пришли через бота, в таблицы вносить не нужно: о них система узнаёт из опроса
через четыре месяца.

## 8. Что можно настроить

Все правила оценки — в `config/rubric.yaml`. После правки — `docker compose restart`. Перед правкой
сохраните копию файла: ошибка в отступах не даст боту запуститься.

| Что | Где в файле |
|---|---|
| Веса вопросов | `weight:` у каждого пункта (чем больше, тем сильнее влияет на балл) |
| Пороги оценки «сильная / хорошая / средняя» | `grade_thresholds` |
| Описание программы и направлений | `program_description` — нейросеть задаёт вопросы только о том, что здесь написано |
| Музейные сообщества для анализа страницы ВКонтакте | `vk_analysis.museum_groups` |
| Когда приходит опрос и кого считать успешным | `checkin_survey` |

Тексты бота (приветствие, вопросы анкеты) — в `bot/questionnaire.py`; их лучше менять вместе с разработчиком.

## 9. Если что-то не так

| Что видно | Что сделать |
|---|---|
| Кандидат пишет, а бот молчит | бот не запущен или выключены сообщения сообщества — см. [install.md](install.md), раздел «Если что-то не так» |
| Бот отвечает, но без уточняющих вопросов | не работает ключ GigaChat (закончился лимит или ключ неверный) — бот перешёл на правила, анкеты принимаются |
| Анкеты не приходят в беседу кураторов | сообщество удалили из беседы или номер беседы неверный — напишите в беседе `/id` |
| Анкета есть в беседе, но не в дашборде | обновите страницу дашборда (данные подтягиваются раз в полминуты) |
| В карточке «опыт не разобран» или «проверьте опыт вручную» | у GigaChat есть ограничения тем; прочитайте ответ кандидата сами |
| Балл кажется несправедливым | откройте «Баллы по каждому вопросу» в карточке: видно, за что снято; решение всё равно за вами |
| Нужно вернуть вчерашние данные | копии базы — в `data/backups`, восстановление — в [install.md](install.md) |

Проверить, всё ли настроено: `docker compose run --rm bot python scripts/check_setup.py`.
