# Бот отбора волонтёров ГИМ

Хакатонный проект для волонтёрской программы Государственного исторического музея.
Кандидат заполняет анкету в чат-боте сообщества ВКонтакте. Бот задаёт уточняющие вопросы,
LLM (GigaChat) оценивает анкету по рубрике музея, а куратор видит рейтинг, карточки кандидатов
и аналитику набора в дашборде и выгружает всё в Excel.

Цель — продукт «под ключ»: в НКО нет программистов и аналитиков, поэтому бот и дашборд должны
работать без постоянной поддержки, а интерфейс — быть понятным человеку без знаний статистики.

## Как это устроено

```
Кандидат (ВК) ⇄ bot/vk_bot.py ⇄ bot/engine.py (анкета, уточнения) ⇄ data/bot.sqlite3
                                         │
                       scorer/ (рубрика + GigaChat) → баллы, саммари, вопросы к собеседованию
                                         │
                 dashboard/app.py (Streamlit) → рейтинг, карточки, решения кураторов, Excel
                                         │
          «Взят в команду» → через 4 месяца bot/survey.py: опрос волонтёра → сигнал кураторам о недовольных
                                         │
                bot/retrain.py: ответы опроса — новые метки, модель успеха переобучается сама
```

| Папка | Что внутри |
|---|---|
| `bot/` | Бот: `questionnaire.py` — вопросы анкеты, `engine.py` — диалоговый движок (не зависит от ВК), `inline_questions.py` — уточнение GigaChat сразу после открытого вопроса с проверкой правилами, `followups.py` — уточняющие вопросы в конце анкеты, `application.py` — оценка отправленной анкеты и карточка для кураторов, `survey.py` — опрос волонтёров через четыре месяца, `retrain.py` — самообучение модели на ответах опроса, `storage.py` — SQLite, `vk_bot.py` — адаптер vkbottle |
| `scorer/` | Оценка анкеты: `rules.py` — пункты по правилам, `extract.py` — LLM-пункты с проверкой цитат, `score.py` — факторы и индекс, `llm.py` — клиенты GigaChat и OpenRouter с кэшем |
| `dashboard/` | Дашборд кураторов: `app.py` — каркас и боковая панель, `overview.py`, `candidates.py`, `candidate.py`, `volunteers.py` — разделы, `data.py` — загрузка и пересчёт по весам, `export.py` — Excel |
| `config/` | `rubric.yaml` — рубрика и веса представителя (единственный источник правды о баллах), `model.json` — коэффициенты модели вероятности успеха |
| `scripts/` | Подготовка данных и проверки: очистка анкет, скоринг, модель, самотест, симулятор бота |
| `data/` | Рабочие данные — **не в git**, см. `data/README.md` |
| `docs/`, `deploy/` | Инструкция по установке для музея, настройка HTTPS (Caddy); `Dockerfile` и `docker-compose.yml` — в корне |
| `bot-architecture.html` | Проектный документ: архитектура, сценарий диалога, макет дашборда |

## Быстрый старт

```bash
pip install -r requirements.txt
cp .env.example .env        # и заполнить ключи
```

Проверка без ВКонтакте и без ключей — полный сценарий анкеты в консоли:

```bash
python scripts/simulate_bot.py          # сценарий с проверками
python scripts/simulate_bot.py --chat   # ручной диалог
python scripts/selftest_scorer.py       # самотест скоринга
python scripts/selftest_inline.py       # самотест уточнений GigaChat и их проверки
python scripts/selftest_survey.py       # опрос через 4 месяца, сигнал кураторам, самообучение модели
```

После `selftest_survey.py` остаётся демобаза с вымышленными волонтёрами — на ней видно раздел «Волонтёры»:

```bash
GIM_BOT_DB=data/selftest_survey.sqlite3 streamlit run dashboard/app.py --server.port 8502
```

Запуск:

```bash
python -m bot.vk_bot                    # бот (нужны VK_GROUP_TOKEN и ключ GigaChat в .env)
streamlit run dashboard/app.py          # дашборд на http://localhost:8501
python scripts/check_setup.py           # проверить .env и ключи перед запуском
```

Для музея — всё в Docker одной командой: бот, дашборд и резервные копии базы раз в сутки
(`docker compose up -d --build`). Пошаговая инструкция для человека без опыта программирования —
[docs/install.md](docs/install.md).

Посмотреть систему без ключей и настоящих анкет — демонстрация на вымышленных кандидатах:

```bash
python scripts/make_demo.py             # data/demo.sqlite3: 28 кандидатов, решения, опрос, версия модели
GIM_BOT_DB=data/demo.sqlite3 GIM_DEMO=1 streamlit run dashboard/app.py --server.port 8502
docker compose --profile demo up -d --build demo   # то же в Docker
```

## Данные и модель (исторические анкеты)

Исходные таблицы музея передаются отдельно и кладутся куда угодно вне репозитория:

```bash
python scripts/clean_anketa.py --in2024 "Анкеты 2024 осень.xlsx" --in2025 "Анкеты 2025 весна.xlsx" --out data
python scripts/score_anketa.py --provider auto     # LLM-оценки 112 анкет (≈ 340 вызовов, кэшируются)
python scripts/model_success.py                    # факторный анализ и модель → config/model.json
```

Что известно на сейчас (112 анкет, 44 взятых волонтёра с часами активности):

- Балл куратора 0–3 почти целиком объясняется длиной ответов и реальную активность не предсказывает.
- Индекс по весам представителя предсказывает активность лучше балла куратора:
  AUC 0,61–0,63 против 0,37–0,48 при порогах 10/20/30 часов в год. Интервалы широкие (±0,17).
- Модель поправок к экспертным весам пока ничего не добавляет — данных мало. Анкеты 2017–2023 гг. запрошены.

## Опрос через четыре месяца и самообучение модели

1. Куратор ставит в карточке кандидата решение «Взят в команду».
2. Через 120 дней (`checkin_survey.after_days` в `rubric.yaml`, для показа — `SURVEY_AFTER_DAYS=0` в `.env`)
   бот сам пишет волонтёру: шесть коротких вопросов — доволен ли, оправдались ли ожидания (словами его анкеты),
   останется ли, сколько часов уделяет, посоветует ли друзьям, что изменить. Одно напоминание через 3 дня,
   через 14 дней без ответа опрос закрывается.
3. Если волонтёр недоволен или не уверен, что останется, бот пишет об этом в беседу кураторов.
4. Ответ «продолжу и уделяю от 5 часов в месяц» — метка «успешный волонтёр» (правило — `checkin_survey.success`).
   Когда новых меток набирается 5, бот переобучает модель на прошлых наборах и опросах, проверяет её leave-pair-out
   и оставляет, только если она ранжирует не хуже действующей. Версии — в таблице `model_versions`,
   история — в разделе «Волонтёры» дашборда. Вручную: `python scripts/retrain_model.py [--force]`.

## Как работаем вдвоём

- `main` — рабочая версия. Новые функции — в отдельных ветках: `feature/<что-делаем>`, исправления — `fix/<что>`.
- Изменения в `main` — через pull request, после того как `simulate_bot.py` и `selftest_scorer.py` проходят.
- **Никогда** не коммитим `.env`, выгрузки анкет, базу бота, логи и кэш LLM — там персональные данные и ключи.
- Код пишем просто и понятно: его будем объяснять команде и представителю музея.
