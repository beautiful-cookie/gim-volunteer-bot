# Контекст проекта для Claude Code

Бот отбора волонтёров ГИМ (ВКонтакте) + LLM-скоринг анкет + дашборд кураторов. Общее описание и команды — в README.md.

## Правила работы

- Код писать просто и понятно, как человек: короткие функции, говорящие имена, явные циклы и if,
  docstring и комментарии на русском там, где неочевидно «зачем». Код будут объяснять команде НКО.
- Персональные данные кандидатов (ФИО, даты рождения, ответы, база бота, кэш LLM) никогда не коммитить
  и не выводить без нужды. Всё это лежит в `data/` и в `.gitignore`.
- В LLM не передаём ФИО, почту и дату рождения — только тексты ответов и итог проверки ФИО.
- Баллы и веса меняются только в `config/rubric.yaml`; код читает рубрику оттуда.
- Перед изменениями в боте прогонять `python scripts/simulate_bot.py`, в скоринге — `python scripts/selftest_scorer.py`.

## Ключевые решения и находки

- Балл куратора 0–3 ≈ длина анкеты (ρ = 0,62, приглашение по длине AUC 0,86), но активность не предсказывает.
  Поэтому модель учим на реальной активности (часы в год), а рубрика оценивает конкретику, а не объём.
- Столбец «Активность в часах в год» в таблицах музея — это СУММА за всё время; `hours_per_year` = сумма / годы
  (минимум 0,5 года). В листах 2024 г. длительность — формулы YEARFRAC с датой выхода (TODAY() = ещё в программе).
- Листы 2024 г. содержат только приглашённых (нет баллов 0) — модель приглашения учится только на весне 2025.
- Веса вопросов — от представителя (таблица «ГИМ вопросы анкеты веса.xlsx»); вес фактора = сумма весов его вопросов.
  Пункты `geography` и `form_quality` предложены командой (`proposed: true`).
- AUC на 44 метках оценивать leave-pair-out (`scripts/model_success.py`): обычный LOO даёт сильное смещение вниз.
- LLM: GigaChat-2-Max (бесплатно для физлиц, для юрлица скорее нужен платный пакет). 3 прогона, медиана,
  цитаты проверяются на вхождение в анкету (80 % слов по первым 5 буквам), категории опыта — ещё и по ключевым словам.
- Уточнения по ходу анкеты (`bot/inline_questions.py`): после «Опыт», «Хобби», «Почему ГИМ», «Ожидания» быстрая модель
  (GIGACHAT_FAST_MODEL, по умолчанию GigaChat-2 = Lite) формулирует один вопрос с цитатой из ответа; проверка правилами
  из `followup_guard` в rubric.yaml (цитата, «вы», чувствительные темы, термины только из описания программы или слов кандидата).
  Не больше 3 за анкету; не прошло — заготовленный переспрос. Блок в конце анкеты после них короче.
- Уточняющие вопросы в конце: правила + LLM выбирает из банка по номерам, свой вопрос — не больше одного и только с цитатой.
  Модель знает о программе только `program_description` из rubric.yaml — иначе придумывает форматы (был вопрос «про аутистов»).
- Windows: сертификат api.vk.ru (HARICA) не в системном хранилище — `SSL_CERT_FILE=certifi.where()` до импорта vkbottle.
- Без пакета `loguru` vkbottle падает при логировании ошибок и прячет настоящее исключение.

## Где что

- Сценарий анкеты и тексты бота — `bot/questionnaire.py`; логика диалога — `bot/engine.py`.
- Карточка для кураторов и жёлтые флаги — `bot/application.py`.
- Решения кураторов — таблица `decisions` в `data/bot.sqlite3` (ключ `bot:<id>` или `hist:<id>`).
- Конфигурация запуска дашборда для превью — `.claude/launch.json` («dashboard», порт 8501).
